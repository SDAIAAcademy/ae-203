Lab 3.1 · step 4

SQLite's full-text index ships with Python and ranks with BM25

db.execute("CREATE VIRTUAL TABLE chunks USING fts5(ref, page, body)")
db.executemany("INSERT INTO chunks VALUES (?, ?, ?)",
               [(c["ref"], c["page"], normalise(c["text"])) for c in chunks])
db.execute("SELECT ref, page FROM chunks WHERE chunks MATCH ? "
           "ORDER BY bm25(chunks) LIMIT 3", ('"claim" OR "delay" OR "refund"',))

FTS5 is a SQLite extension; the sqlite3 module of the Python builds used for this course (laptop and Colab) includes it, and the lab fails early if yours does not. For a corpus of this size it is all a service needs: one file, no server. Larger corpora move to a search engine or a database with full-text and vector indexes (pgvector is one example).

Sources: SQLite FTS5 documentation.

Lexical search

BM25 rewards rare query words and stops counting repeats

  • A word that appears in few chunks ("bicycle") counts more than a common one ("metro").
  • The tenth repeat of a word adds little; a long chunk is not favoured for being long.
  • Exact words only: "refunded" does not match "refund" unless something stems them.
0.90
hit@1 on the 30 questions, normalised tokens, rank-bm25

rank-bm25 is the library in the lab; SQLite FTS5 uses the same ranking family. BM25 is still the baseline every retrieval paper compares against: cheap, explainable, strong on names and numbers (route ids, policy numbers).

Sources: rank-bm25 repository.

Dense search

Vectors match what exact keywords miss: word pieces here, meaning with embeddings

In the lab: a stand-in

Character 3- to 5-gram weights, cosine similarity, computed on the laptop: "استرداد" and "الاسترداد" share most pieces. It matches spelling, not meaning.

In production: embeddings

Dense vectors learned by a model, so "fare cap" lands near "maximum daily charge"; kept in an index such as FAISS, pgvector or Chroma.

No model download. The course computes its vectors from the text itself, so they are not learned embeddings. The interface is the same: text in, vector out, nearest vectors back.

Say plainly that character n-grams are a stand-in for learned embeddings, chosen so nothing is downloaded. They capture spelling, not meaning: "fare cap" and "maximum daily charge" would not match. With an embedding model the same code would add meaning. The lab's vectors are sparse counts, not the dense vectors the session title names: say so, and that only the interface carries over. They scored 0.90 hit@1 too, but on different questions, which is why fusion helps.
